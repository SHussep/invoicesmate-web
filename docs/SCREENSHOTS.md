# Screenshot production

Capture date: 2 October 2026 (Australia/Sydney).

## Source and fidelity

The screenshots are rendered by the actual Flutter application in an iPhone simulator. App source: `SHussep/UniversalInvoicesMate`, commit `3d45a9a`. A separate working copy was built for capture; the original app checkout was not edited.

A local Firebase demo project (`demo-invoices-promo`) supplies fictional Harbour Studio records. Names, email addresses and amounts are demonstration data. No invoices were sent and no payments were processed.

The capture copy uses local Authentication and Firestore emulators. The iOS native ML Kit registrations were excluded only from this copy because those dependencies exclude arm64 simulators. No receipt scanning or machine translation is demonstrated in these screenshots. Screen layouts, widgets and themes remain the application's own implementation.

## Assets

- `dashboard.png`: business overview, light theme.
- `invoices.png`: invoice list and payment status.
- `invoice-preview.png`: real PDF preview generated by the application.
- `expenses.png`: sample expense records.
- `reports.png`: business reports.
- `export.png`: financial-year export controls.
- `dashboard-dark.png`: the same overview in dark theme.

The original files are PNG. Website copies are encoded as WebP at full resolution and at 660 px width. Image contents are not redrawn or AI-generated. Responsive image selection, dimensions and lazy loading are defined in the HTML.

The phone borders and typography in `marketing/` are editable HTML/CSS. This keeps the captured interface unchanged inside the composition. The marketing templates are not included in the hosting allowlist.

## Reproduction

1. Use an isolated copy of the application with a local demo backend, never customer records.
2. Run Authentication and Firestore emulators on 127.0.0.1, ports 9199 and 8199.
3. Build and install the capture copy in the iPhone simulator. Use English, light mode and a consistent 9:41 status bar.
4. Navigate to each screen and wait until loading indicators disappear. Review displayed data before capture.
5. Capture full-resolution PNG with `xcrun simctl io <device-id> screenshot <output.png>`.
6. Switch to dark mode in the app and repeat the dashboard capture.
7. Encode full-size and 660 px WebP derivatives. Preserve the originals separately.
8. Open each `marketing/*.html` template locally and capture at its fixed canvas dimensions: social 1200 × 630; portrait cards 1080 × 1350.

All public-facing screenshots should retain the site's fictional-data caption. Re-capture after changes to app navigation or visual design.

## Observations in this app build

The light-theme status icons on the invoice and expense lists are white on a pale background. These are captured faithfully; no interface pixels were repainted. The screenshots show the development source above, so verify feature availability against the App Store build before release.
